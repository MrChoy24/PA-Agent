# PA Agent 服务器部署指南（无头守护进程）

本文档把 PA Agent 从「Windows 桌面程序」变成「服务器上 7×24 跑的守护进程」：
拉 K 线 → 两阶段 AI 分析 → 钉钉/PushPlus 推送 → 自动下单。没有窗口，不装 Qt。

---

## 一、它到底是什么

`pa_agent/daemon/` 是一个**新的入口**，不是新的一套逻辑。它复用桌面版同样的引擎：

| 阶段 | 复用的模块 | 说明 |
| --- | --- | --- |
| 行情 | `pa_agent/data/` | 和桌面版同一个 `BinanceSource` / `OKXSource` |
| 快照 | `pa_agent/data/snapshot.py` | 同一个 `build_analysis_frame`，只喂已收盘K线 |
| 分析 | `pa_agent/orchestrator/two_stage.py` | **同一份提示词、同一个两阶段引擎** |
| 记录 | `pa_agent/records/` | 同样写 `records/pending/` 与 `trade_records/` |
| 推送 | `pa_agent/notify/` | 同样走钉钉加签 / PushPlus |
| 下单 | `pa_agent/trading/` | 同样走 `AutoTrader` 的 9 道闸门 |

区别只在**没有界面**，以及多了几个服务器专属参数（轮询间隔、冷却、日志级别）。

`pa_agent/daemon/` 全目录**零 PyQt6 依赖**（有单元测试守着这条线）。

## 二、最快的路径：Docker

### 2.1 准备文件

把仓库拷到服务器（假设在 `/opt/pa-agent`）：

```bash
cd /opt/pa-agent
cp .env.example .env
chmod 600 .env
```

### 2.2 填 `.env`

最少要填这三项：

```ini
# DeepSeek 的 API Key
PA_AGENT_API_KEY=sk-xxxxxxxxxxxxxxxx

# 盯哪个品种、什么周期
PA_DAEMON_SYMBOL=BTCUSDT
PA_DAEMON_TIMEFRAME=15m
```

要推送钉钉就再加：

```ini
DINGTALK_WEBHOOK_URL=https://oapi.dingtalk.com/robot/send?access_token=xxxx
DINGTALK_SECRET=SECxxxxxxxxxxxx
```

### 2.2.1 备用 GLM 通道（可选）

主通道是**火山方舟**或 **SenseNova 网关**时，可以再挂一条智谱 `glm-4-flash` 兜底：

```ini
PA_AGENT_GLM_API_KEY=你的智谱Key
```

- Key 在 <https://open.bigmodel.cn> 申请，`glm-4-flash` 有免费额度。
- 模型名（`glm-4-flash`）和 Base URL（`https://open.bigmodel.cn/api/paas/v4`）**写死在代码里**，不用你填。
- 也认 `GLM_API_KEY` / `ZHIPU_API_KEY` 两个旧名，任填一个即可。
- **生效条件**：主通道必须是方舟或 SenseNova。若 `PA_AGENT_API_BASE` 是 `https://api.deepseek.com`，这行会被忽略（官方通道本身够稳，不需要兜底）。
- **它在链尾**：方舟那 12 个模型全试完才会轮到它。想让 GLM 更早生效，得在 `config/settings.json` 里精简方舟的 `fallbacks` 数量。

真要自动下单，再加交易所凭据（**不填就只分析、不下单**）：

```ini
OKX_API_KEY=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
OKX_API_SECRET=XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
OKX_PASSPHRASE=你的passphrase
PA_DAEMON_AUTO_TRADE=true
PA_DAEMON_DRY_RUN=true      # 先观察一周，确认没问题再改 false
PA_DAEMON_VENUE=okx         # 想用币安就写 binance
```

Binance 对应的是 `BINANCE_API_KEY` / `BINANCE_API_SECRET`（可选 `BINANCE_TESTNET=true` 走测试网）。

> **为什么 Key 放环境变量而不是 settings.json**
> 服务器上把密钥写进文件，容易在备份、同步、`docker cp` 时泄漏。
> 环境变量优先级高于 `config/settings.json`，轮换密钥只要改 `.env` 再 `docker compose up -d`。
> AI Key、钉钉、交易所凭据、自动交易三开关都支持环境变量；
> **数字风控（置信度、单笔上限、杠杆、保证金模式）只放 settings.json**，
> 避免 `.env` 里一个拼写错误就把风控放宽。

### 2.3 准备配置目录

容器会挂载宿主机的 `./config`。先放一份配置进去：

```bash
mkdir -p config logs trade_records records
cp config/settings.example.json config/settings.json
```

> **目录属主不用你操心**：镜像的入口脚本会以 root 启动、把这四个挂载
> 目录的属主改成 `10001`，再用 `setpriv` 降权到 `10001` 运行。所以在
> 1Panel 里由 root 创建的目录也不会报 `Permission denied`。
> 若你希望用别的 UID（比如宿主机上已有的 `1000`），设
> `PA_AGENT_UID=1000 PA_AGENT_GID=1000` 即可。

`settings.json` 里真正需要在服务器上改的只有：

| 字段 | 建议值 | 说明 |
| --- | --- | --- |
| `provider.model` | `deepseek-chat` | 服务器通常用正式模型 |
| `general.analysis_bar_count` | `100` | 喂给 AI 的K线根数 |
| `general.decision_confidence_threshold` | `60` | 低于这个置信度不推送、不下单 |
| `dingtalk.enabled` | `true` | 配合 `.env` 里的 Webhook |
| `auto_trade.enabled` | `false` | **先保持 false，跑通再说**（也可用 `PA_DAEMON_AUTO_TRADE` 覆盖） |
| `auto_trade.dry_run` | `true` | **先保持 true**（也可用 `PA_DAEMON_DRY_RUN` 覆盖） |
| `auto_trade.venue` | `binance` | 在哪下单，可与行情源不同（也可用 `PA_DAEMON_VENUE` 覆盖） |
| `auto_trade.market_type` | `spot` | 想下合约就改 `futures`（需先开通合约账户 + Key 勾「合约交易」） |
| `auto_trade.margin_per_trade_usdt` | `10.0` | 合约每单保证金（USDT），名义 = 保证金 × 杠杆；**全仓模式下不生效** |
| `auto_trade.leverage` | `1` | 杠杆 1~125，现货强制 1 |
| `auto_trade.order_type` | `MARKET` | `MARKET` 市价 / `LIMIT` 限价 |
| `auto_trade.margin_mode` | `isolated` | 逐仓 / 全仓 |
| `auto_trade.max_price_deviation_pct` | `0.3` | 跨所价差保护：行情源与下单所价差超过该百分比就跳过本次下单；`0` = 关闭 |

### 2.4 构建并启动

```bash
docker compose build
docker compose up -d
docker compose logs -f
```

看到这些就说明跑通了：

```
PA Agent 守护进程自检  ·  source=binance symbol=BTCUSDT tf=15m ... 结果：健康 ✅
数据源就绪：BinanceSource
分析引擎就绪（provider=deepseek-chat）
守护进程启动：source=binance symbol=BTCUSDT tf=15m bars=100 poll=20s ...
开始分析 BTCUSDT 15m（100 根）…
分析完成：order_type=限价单 confidence=72
自动交易：executed=True dry_run=True reason=dry-run
```

## 三、不用 Docker：直接跑（systemd）

### 3.1 装依赖

```bash
cd /opt/pa-agent
python3.11 -m venv .venv
.venv/bin/pip install -r requirements-daemon.txt
```

`requirements-daemon.txt` 刻意不含 PyQt6 / pyqtgraph / A股依赖，装出来大约 120MB（对比桌面版 600MB）。

### 3.2 先自检

```bash
.venv/bin/python -m pa_agent.daemon --health-check
echo $?      # 0 = 健康，1 = 有问题
```

### 3.3 装成服务

```bash
sudo cp deploy/pa-agent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now pa-agent
sudo journalctl -u pa-agent -f
```

## 四、命令行参数

```bash
python -m pa_agent.daemon [选项]
```

| 参数 | 作用 |
| --- | --- |
| `--health-check` | 只自检（配置 / 行情 / 通知），不分析。**退出码 0 = 健康** |
| `--once` | 跑一轮就退出（拉行情 + 分析一次），调试用 |
| `--symbol ETHUSDT` | 换品种（默认读 `settings.json`） |
| `--timeframe 1h` | 换周期 |
| `--data-source okx` | 换交易所 |
| `--bar-count 120` | 换分析根数 |
| `--poll-interval 30` | 轮询间隔秒 |
| `--analysis-cooldown 300` | 两次分析最小间隔秒 |
| `--analyze-on-start` | 启动立刻分析一次，不等收盘 |
| `--dry-run-trade` | **强制试运行**，即使配置里是真实下单 |
| `--log-level DEBUG` | 日志级别 |
| `--settings /path/to/settings.json` | 指定配置文件 |

环境变量同名对应（`PA_DAEMON_*`），见 `.env.example`。

## 五、自动交易：从试运行到真单

这是最容易出事的一步，按顺序来。

### 第 0 步：确认闸门

自动交易有 9 道闸门，全部通过才会下单：

```
总开关 enabled → 置信度 ≥ min_confidence → 决策里有下单意图
→ 有有效止损（require_stop_loss）→ 在白名单内（allowed_symbols）
→ 今日已下单数 < max_daily_orders → 金额收敛到 max_notional_usdt
→ 试运行？是→只记录 ；否→真实下单
```

每日单数**跨重启延续**：`AutoTrader._count_today_orders()` 读
`trade_records/auto_orders.jsonl`，按 UTC 日期统计 `executed=True 且 dry_run=False` 的记录。
所以重启容器不会重置额度。

### 第 1 步：只试运行，观察一周

`config/settings.json`：

```json
"auto_trade": {
  "enabled": true,
  "dry_run": true,
  "venue": "binance",
  "min_confidence": 70,
  "max_notional_usdt": 20.0,
  "max_daily_orders": 5,
  "allowed_symbols": ["BTCUSDT"],
  "require_stop_loss": true
}
```

看 `trade_records/auto_orders.jsonl`，每行是一次评估：

```bash
tail -f trade_records/auto_orders.jsonl | jq .
```

重点看 `reason` 字段：`dry-run` 表示过了所有闸门只差执行；其它值说明被哪道闸门拦下了。

### 第 2 步：交易所 API Key 权限（**关键**）

| 项目 | 要求 |
| --- | --- |
| 权限 | **只勾「现货交易」**，不要勾「提币」。要跑合约时再额外勾「合约交易」 |
| IP 白名单 | **必须填服务器公网 IP**。不填白名单的 Key 一旦泄漏就是灾难 |
| 子账户 | 建议单独开子账户，只放计划内的资金 |
| OKX 额外 | 需要 Passphrase；测试可开「模拟盘」（`okx.demo=true`） |
| 合约额外 | 账户要先开通 U 本位合约（OKX 还需把资金从资金账户划到交易账户），否则报 `-2015` / `51010` |

查服务器公网 IP：

```bash
curl -s https://api.ipify.org && echo
```

### 第 3 步：小额度真单

```json
"dry_run": false,
"max_notional_usdt": 10.0,
"max_daily_orders": 2
```

然后 `docker compose restart`，盯着 `trade_records/auto_orders.jsonl` 和交易所 App。

**随时可以一键刹车**：

```bash
# 方式一：改配置
sed -i 's/"enabled": true/"enabled": false/' config/settings.json
docker compose restart

# 方式二：直接停容器
docker compose stop
```

## 六、最低配置与选购

### 6.1 实测资源占用

| 项目 | 数值 |
| --- | --- |
| 冷启动到就绪 | ~2 秒 |
| 常驻内存（RSS） | **实测 38 MB**（导入 daemon + 构建分析引擎后）；装 matplotlib 画交易记录图会涨到约 90–120 MB |
| CPU | 每小时分析 4 次时 < 3%，几乎是 idle |
| 磁盘 | 镜像 ~180 MB + 数据每月 < 100 MB |
| 出网流量 | 每月 < 1 GB |

**结论：1 核 512M 都能跑，1 核 1G 更稳**，2 核 2G 从容（留出系统更新余量）。

### 6.2 选购建议

| 场景 | 推荐 | 参考月价 |
| --- | --- | --- |
| 只盯 1–2 个品种 | 1C1G 轻量应用服务器 | ¥24–40 |
| 多品种 + 想同时跑桌面版 | 2C4G | ¥60–100 |
| 对延迟敏感（做短线） | 2C2G，选东京/新加坡节点 | ¥80–150 |

**选机要点**：

1. **必须能访问 Binance / OKX**。国内机房直连 `api.binance.com` 通常不通，
   优先选**香港 / 东京 / 新加坡**节点。买之前先测：

   ```bash
   curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://api.binance.com/api/v3/time
   curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://www.okx.com/api/v5/public/time
   ```

   两个都返回 `200` 且耗时 < 1 秒才适合部署。

2. **要求 Docker**（或者至少 Python 3.11+）。很多「轻量应用服务器」预装宝塔不含 Docker，
   选「纯净系统」镜像（Ubuntu 22.04 / Debian 12）自己装最省事。

3. **不要选 Windows 服务器**。桌面版才有界面，守护进程用 Linux 更稳、更省内存。

4. 交易所 API 需要**固定公网 IP**，所以别用会漂移 IP 的 P2P 组网方案做主路径。

### 6.3 国内服务器怎么办

如果只能用国内机器（比如已有阿里云/腾讯云），有两条路：

- **走代理**：给容器设 `HTTPS_PROXY`，但 `pa_agent/data/binance_source.py`
  只做主机切换不做代理认证，需要在 `httpx.Client(proxy=...)` 上加配置（未实现，需改代码）。
- **换数据源**：目前守护进程只支持 Binance / OKX 两家，都需外网直连。

**结论：优先买境外节点**，比折腾代理省事得多。

## 七、运维

### 7.1 看日志

```bash
docker compose logs -f --tail 100
# 或看文件（含完整 DEBUG）
tail -f logs/pa_agent.log
```

日志文件 5MB × 10 份轮转，不会撑爆磁盘。

### 7.2 健康检查

Dockerfile 里已配 `HEALTHCHECK`（每 5 分钟真的拉一次行情）：

```bash
docker inspect --format '{{.State.Health.Status}}' pa-agent
# healthy / unhealthy
```

### 7.3 数据备份

只需要备份两个目录：

```bash
tar czf pa-agent-$(date +%F).tar.gz config/ trade_records/ records/
```

`config/` 里有密钥，备份文件自己加密。

### 7.4 升级

```bash
cd /opt/pa-agent
git pull                      # 或重新上传代码
docker compose build
docker compose up -d
```

`config/` `logs/` `trade_records/` `records/` 都是挂载卷，升级不丢。

### 7.5 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `确认健康 ❌ 行情自检失败` | 服务器连不上交易所，见 6.2 第 1 条 |
| `AI API Key 未配置` | `.env` 里 `PA_AGENT_API_KEY` 没填，或容器没重启 |
| `分析异常：401` | Key 错或额度用完 |
| `Binance 错误 -2014: API-key format invalid` | 交易所 Key 填错，或复制时带了空格 |
| `Binance 错误 -2015: Invalid API-key, IP, or permissions` | **IP 白名单没加服务器 IP**，或没开现货交易权限 |
| 一直 `等待当前K线收盘` | 正常。`wait_bar_close=true` 时只在收盘后分析 |
| 一直 `冷却中` | `PA_DAEMON_ANALYSIS_COOLDOWN` 设太大了 |
| 钉钉没收到 | 先 `--health-check`，再看 `logs/pa_agent.log` 里的 `errcode`；`310000` = 加签错 |

## 八、和桌面版的关系

两个可以**同时跑**，互不干扰：

- 桌面版：`运行智能体.bat`（Windows，有界面，手工点「提交分析」）
- 服务器版：`python -m pa_agent.daemon`（Linux，无界面，自动轮询）

它们共享同一套 `config/settings.json` 格式（但各自一份文件）、
同一套 `prompt_engineering/` 提示词、同一套 `trade_records/` 记录格式。

**注意**：如果两个都开了自动交易，会用**同一份** `auto_orders.jsonl` 统计每日单数——
这其实是好事（额度共享）。但请不要让两台机器盯同一个品种同一周期做自动交易，
会重复下单。

## 九、安全清单

上线前逐条确认：

- [ ] `.env` 权限 600，且不在 git 里（`.gitignore` 已含 `.env`）
- [ ] 交易所 API Key 只勾「现货交易」，不勾「提币」
- [ ] 交易所 API Key 已配 IP 白名单 = 服务器公网 IP
- [ ] 自动交易用**子账户**，只放计划内资金
- [ ] 先跑 `dry_run: true` 至少一周，确认 `auto_orders.jsonl` 的决策合理
- [ ] `max_notional_usdt` 设成自己心疼但不致命的额度
- [ ] 服务器 SSH 关闭密码登录，只用密钥
- [ ] 防火墙只开 22 端口（守护进程不监听任何端口）
