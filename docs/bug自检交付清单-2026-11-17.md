## 二、自动交易层（P0 — 资金安全）

### T1. 限价单查不到成交状态被当成「已成交」
- 位置：pa_agent/trading/okx_trader.py:1298-1300（原 :1267-1269）
- 现象：`_order_fill_info` 在网络失败时返回空 state，旧判定 `filled = (type_l != "limit") or fill_state == "filled" or (not fill_state)` 把「查不到」当成交 → 未成交就挂保护单（三条腿全被 51023/51279 拒）并推虚假成交回报（2026-11-17 04:10 钉钉误报事故）。
- 修复：只认 `state == "filled"` 或 `fill_sz > 0`；其余一律 `filled=False`，走 `pending_fill` + `resume_pending_trigger()` 补偿链路。
- 验证：模拟盘流程 A（限价单未成交）→ `reason=pending-fill`、`filled=False`，补偿链路连调 3 次保持等待，不再宣称成交。

### T2. 补偿链路把「查不到」当成交 + partial 落终态
- 位置：pa_agent/trading/auto_trader.py:1105-1152（`_pending_order_fill`）、:745-860（resume 闸门）
- 现象一：`known=False` 时旧代码直接按持仓兜底并 `fill_confirmed=True`。
- 修复：新增 `_RESUME_UNKNOWN_LIMIT = 3`，前 2 轮只告警等待，第 3 轮才按持仓兜底且 `fill_confirmed` 保持 False；通知层据此改发「未确认成交」核对提示。
- 现象二：只挂上部分保护单时落 `partial` 终态，`_last_pending_trigger()` 直接跳过 → 缺的腿永远补不上（2026-11-17 多头只有止盈、裸奔事故）。
- 修复：`deliverable = total - 计划本身有问题的腿`；`ok_count < deliverable` 时计次重试（最多 3 次），最终才落 `gave-up` 并 ERROR 提示立即人工补挂；`_last_pending_trigger()` 对 `partial` 继续观察。

### T3. 旧仓止损顶掉新仓止损（幂等误判）
- 位置：pa_agent/trading/okx_trader.py:1477-1615
- 现象：`replace_on_mismatch=False` 分支只要是「有同向止损」就整体跳过，不看价位；上一笔仓位的旧止损会让新仓止损挂不上。
- 修复：`existing_sl_all = sl_matches if want_sl > 0 else bool(existing_sl_rows)`（价位一致才算在场）；价位不一致时由 51088 被拒分支撤旧重挂（新增 `_STOP_LOSS_CONFLICT_CODE = "51088"`）。
- 止盈侧：新增 `_tp_covers(row, price, contracts)` —— 同价且张数够才算在场，加仓后旧止盈张数不足会被补挂（模拟盘流程 E 实测复现并修复：原先持仓 0.2 张、止盈总量仅 0.1 张）。

### T4. tdMode 与持仓保证金模式不一致
- 位置：okx_trader.py:153（`_MARGIN_MODE_REJECT_CODES = {"51023", "51169"}`）、:1662-1760（挂单自愈）；auto_trader.py（`_held_position_detail` + env 对齐）
- 现象：GUI 与诊断脚本路径没有 env 覆盖步骤 → 下单 cross、挂保护单 isolated → 51023「Position doesn't exist」。
- 修复：① `AutoTrader.__init__` 按 `PA_DAEMON_MARGIN_MODE` 严格对齐；② `get_positions()` 返回 `margin_mode`，挂保护单传持仓真实 mgnMode；③ 遭 51023/51169 时翻转 tdMode 重试一次。
- 验证：容器内故意以 `margin_mode="isolated"` 构造，实际落到 cross；模拟盘六条条件单 tdMode 全对。

### T5. Binance 保护单没有幂等
- 位置：pa_agent/trading/binance_trader.py:1104-1380
- 现象：`replace_on_mismatch` 被 `# noqa: ARG002` 忽略，补偿链路每轮重挂同一批条件单。
- 修复：挂单前按 `type + stopPrice` 比对在挂单；止损同价跳过、止盈还要求 `origQty` 覆盖本仓所需；换价位重建止损时只在新单成功后才撤旧单（避免裸奔窗口）。

## 六、模拟盘全流程实测记录（OKX demo=True）

| 流程 | 场景 | 结果 |
|---|---|---|
| A | 限价单未成交 | `pending-fill`，补偿链路 3 轮等待，未误称成交 |
| B | 突破单（trigger） | 正常挂单；补偿链路按 algoId 语义跳过回查 |
| C | 价差护栏 | 等待单走「差距 > 止损距离 × 3」判据，正常拦截 |
| D | 市价单开仓 | 止损 `closeFraction=1 + reduceOnly=true + sz 空`，止盈按张数分批 |
| E | 加仓后整仓重挂 | 幂等按价位+张数判定，止盈总量跟随持仓（修复前只有一半） |
| F | 清理 | 撤单 + 平仓 → 持仓 0 / 挂单 0 / 条件单 0 |

模拟盘与实盘差异（已记录）：demo 为 net_mode，实盘为 long_short_mode；`place_protections` 在 net_mode 下不传 posSide。
