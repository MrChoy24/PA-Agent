# 下单 / 止盈止损参数总表（PA Agent）

> 版本：2026-11-17（全面自检后的代码）  
> 依据：`pa_agent/config/settings.py`、`pa_agent/trading/auto_trader.py`、`pa_agent/trading/common.py`、`pa_agent/trading/okx_trader.py`、`pa_agent/trading/binance_trader.py`、`pa_agent/daemon/config.py`。  
> 表里的数字都是**代码默认值**；线上实际值以 `config/settings.json` 的 `auto_trade` 段与服务器 `/opt/pa-agent/.env` 为准。

## 0. 一句话链路

```
AI 决策(STAGE2 JSON)
   → AutoTrader 闸门链 Gate 1…Gate 10（是否下单、下多少、什么价）
   → 交易所下单（现货或 U 本位永续；市价 / 限价 / 计划委托）
   → 成交则立刻挂条件单：止损 + TP1 + TP2（交易所侧常驻）
   → 未成交则记 pending_fill / pending_trigger，由轮询里的 resume_pending_trigger() 在成交后补挂
```

核心原则：**保护单挂在交易所侧**，程序崩了/容器重启/断网都不影响止损止盈生效；程序只负责“挂上去”和“补挂”，不靠程序自身盯盘来止损。

## 1. 决策侧字段（AI 输出，程序读这些键）

| 字段 | 含义 | 取值/归一化 | 缺失或非法时 |
|---|---|---|---|
| `order_type` | 下单方式 | 只认中文三值：`市价单` / `限价单` / `突破单` | Gate 3 拒：`no-order` |
| `order_direction`（或 `direction`） | 方向 | `做多/多/买入/long/buy` → BUY；`做空/空/卖出/short/sell` → SELL | Gate 3 拒：`no-order` |
| `trade_confidence` | 置信度（整数） | 与 `min_confidence` 比较 | Gate 2 拒：`low-confidence` |
| `entry_price`（或 `limit_price` / `price`） | 入场/挂单价 | 依次取第一个 >0 的值；都没有则退回本轮 `last_price` | Gate 7 后拒：`no-price` |
| `stop_loss_price`（或 `stop_loss`） | 止损价 | >0 有效 | `require_stop_loss=True` 时 Gate 4 拒：`no-stop-loss` |
| `take_profit_price` | TP1 价 | >0 有效 | 少挂一条腿（不裸奔，不拒单） |
| `take_profit_price_2` | TP2 价 | 可选（STAGE2 契约里就是可选） | 少挂一条腿 |
| `notional_usdt` / `position_size_usdt` / `order_notional_usdt` / `amount_usdt` | 决策给出的名义金额 | 依次取第一个 >0 的值 | 落 `max_notional_usdt` 再收敛 |

`order_type` 到交易所订单类型的映射：

| 决策中文 | 归一类型 | 含义 |
|---|---|---|
| `市价单` | `MARKET` | 立即成交 |
| `限价单` | `LIMIT` | 按决策价挂单，可能等待回踩/反弹 |
| `突破单` | `TRIGGER` | 计划委托：先挂触发价，价格穿到才按市价进场（仅 OKX 合约真正支持；Binance 退化成 MARKET） |

方向到持仓方向：`BUY → long`、`SELL → short`。**以下单方向为准**，面板配置的 `position_side` 与本次方向冲突时只告警，不采用（否则流水记错方向，补偿补挂会把保护单挂到反向，OKX 回 51280/51279）。

## 2. 面板参数（`config/settings.json` → `auto_trade`，AutoTradeSettings）

| 键 | 默认值 | 作用 | 边界 / 备注 |
|---|---:|---|---|
| `enabled` | `False` | 自动交易总开关 | False 时 Gate 1 拒：`disabled` |
| `dry_run` | `True` | 试运行：只记录“本应下单”，不发单 | True 时走 Gate 9，不碰交易所写接口 |
| `venue` | `binance` | 下单所 | `binance` / `okx` |
| `min_confidence` | `60` | 置信度门槛 | `trade_confidence < 此值` → `low-confidence` |
| `max_notional_usdt` | `50.0` | **单笔名义金额上限（USDT）** | 超额**收敛**不拒单（`clamped=True`）；为 0 且无决策名义 → `notional-invalid` |
| `max_daily_orders` | `10` | 每日最多下单笔数 | `0` = 不限；达到上限 Gate 6 拒：`daily-limit` |
| `allowed_symbols` | `[]` | 交易对白名单 | 空 = 不限；不在名单 Gate 5 拒：`symbol-not-allowed` |
| `require_stop_loss` | `True` | 没有有效止损就拒绝下单 | Gate 4 |
| `market_type` | `spot` | 市场类型 | `spot` 现货 / `futures` U 本位永续 |
| `margin_per_trade_usdt` | `10.0` | 每单保证金（USDT） | **仅逐仓合约生效**；>0 时名义 = 保证金 × 杠杆，再被 `max_notional_usdt` 封顶 |
| `leverage` | `1` | 杠杆倍数 | 合约夹取到 `1…125`；现货强制按 1 |
| `order_type` | `MARKET` | 面板默认订单类型 | 实际以决策的 `order_type` 为准 |
| `margin_mode` | `isolated` | 保证金模式 | `isolated` 逐仓 / `cross` 全仓；**保护单的 `tdMode` 跟持仓真实 mgnMode，不盲从本项** |
| `max_price_deviation_pct` | `0.3` | 跨所价差护栏（%） | `0` = 关闭；见 §4 Gate 8 |
| `protect_after_entry` | `True` | 成交后立刻挂止损/TP1/TP2 | 现货自动跳过（无原生条件单） |
| `tp1_fraction` | `0.5` | TP1 平掉的比例 | TP2 拿剩余；**止损永远保护全量** |
| `max_slippage_bps` | `30.0` | 成交价与决策价偏差告警阈值（bps） | **只告警不拒单**；`<=0` 关闭 |

### 金额与数量换算（Gate 7 / Gate 8.5 / Gate 10）

```
逐仓合约且 margin_per_trade_usdt > 0:
    notional = margin_per_trade_usdt × leverage        # 再被 max_notional_usdt 封顶
其余（现货 / 全仓 / 未填保证金）:
    notional = 决策名义，缺省落 max_notional_usdt      # 再被上限收敛
notional <= 0                     → 拒单 notional-invalid
leverage = clamp(1…125)           # 现货强制 1
margin_usdt = notional / leverage # 仅用于日志与记录展示；全仓由账户余额扣
qty = notional / 参考价            # 参考价见下
```

- **参考价（sizing price）**：`MARKET` 用下单所**实时价**（`_venue_reference_price(force=True)`，分析耗时几分钟，拿决策价换算会超名义）；`LIMIT` / `TRIGGER` 用决策价（限价成交价不会更差）。取不到实时价时告警并退回决策价。
- **张数换算（OKX 合约）**：`张数 = 基础币数量 ÷ (ctVal × ctMult)`，再按 `lotSz` **向下取整**（`ROUND_DOWN`，Decimal 计算）。`ctVal` 取不到或结果 ≤0 时返回 0 → 该腿拒挂，**不做“至少 1 张”兜底**（会把小额单放大）。
- **全仓（cross）忽略 `margin_per_trade_usdt`**：全仓没有“每单固定保证金”概念，保证金由账户可用余额决定。
- **收敛后的保证金反推必须带 `and not clamped`**：否则会用面板保证金把已收敛的名义覆盖回去，出现“名义 20、保证金 100”的自相矛盾。

## 3. 下单闸门链（AutoTrader._evaluate，顺序固定）

| Gate | 判据 | 不通过时的 `reason` |
|---|---|---|
| 1 | `enabled=True` | `disabled: 自动下单未启用（enabled=False）` |
| 2 | `trade_confidence >= min_confidence` | `low-confidence` |
| 3 | 决策是下单意图（中文类型 + 方向可解析） | `no-order` |
| 4 | `require_stop_loss` 为真时必须有有效止损 | `no-stop-loss` |
| 4.5 | **保护单几何预演**（`plan_protections`） | `invalid-protection` |
| 5 | 交易对非空、形如交易对、在白名单内 | `invalid-symbol` / `symbol-not-allowed` |
| 6 | 今日已下单笔数 `< max_daily_orders`（0=不限） | `daily-limit` |
| 7 | 名义金额可算且 >0（超额收敛） | `notional-invalid`；价格缺失 `no-price` |
| 8 | 跨所价差护栏 | `price-deviation` / `price-deviation-pending` |
| 8.5 | 杠杆夹取 `1…125`（现货 1） | 不拒，仅夹取 |
| 9 | `dry_run` → 只返回拟下单结果 | `dry-run`（`executed=False`，`dry_run=True`） |
| 10 | 真实下单 | `submitted` / `pending-fill` / `pending-trigger` / `client-error` 等 |

> Gate 8.5 编号是历史沿革：Gate 8 已被“跨所价差保护”占用，其余 Gate 编号不重排。

### Gate 4.5：保护单几何预演（开仓前就拦）

用与真正挂保护单**同一套** `plan_protections()` 先算一遍，只要某条腿“**给了价**但方向矛盾”就拒绝开仓（`invalid-protection`），避免“开仓成交、三条腿全被交易所拒、仓位裸奔”。缺价不算矛盾（TP2 本来可选）。

### Gate 8：跨所价差护栏（`max_price_deviation_pct`，默认 0.3%）

先判断这张单**会不会立即成交**（`_waits_for_price`）：

- `MARKET`：一定立即成交 → 按百分比护栏卡：`|下单所价 − 决策价| / 决策价 > max_price_deviation_pct` 就拒（`price-deviation`）。
- `TRIGGER`（突破单/计划委托）：设计上就是等价格穿到触发价 → 不按百分比卡，改按**风险距离**：`|现价 − 挂单价| > |挂单价 − 止损价| × 3.0` 才拒（`price-deviation-pending`），常量 `MAX_PENDING_STOP_MULT = 3.0`。
- `LIMIT`：做多挂在现价之上（会立即吃掉）/ 做空挂在现价之下 → 等同市价，走百分比护栏；挂在“等待”那一侧 → 走风险距离护栏。
- 取不到下单所现价 → 保持保守行为（不跳过校验）。

## 4. 保护单：止损 / TP1 / TP2

### 4.1 计划（`plan_protections`）

输入：持仓方向、持仓均价、止损价、TP1、TP2、**整仓数量**、`tp1_fraction`。

几何约束（与决策侧 `trade_metrics` 一致）：

```
做多：stop_loss < entry < tp1 <= tp2
做空：tp2 <= tp1 < entry < stop_loss
```

| 腿 | 触发价 | 数量 | 说明 |
|---|---|---|---|
| 止损 `stop_loss` | 决策 `stop_loss_price` | **全量**（OKX 用 `closeFraction=1` 全平） | 先保命 |
| TP1 `take_profit_1` | 决策 `take_profit_price` | `整仓 × tp1_fraction`（默认 50%） | 分批止盈 |
| TP2 `take_profit_2` | 决策 `take_profit_price_2` | 剩余量 | 可选腿 |

规则：

- 价格缺失 / 非正 / 方向反了 → 该腿跳过并给出中文原因，**不整体放弃**（止损能挂就先挂止损）。
- **按“整个持仓”而不是“本笔成交”挂**：挂之前先查 `_held_position()`，用持仓数量与均价覆盖 `qty` / `entry_price`，否则加仓后止盈会叠成 4 条、每条只按本笔量算。
- 触发价按交易所 `tick` 用 `floor_to_precision` **向下取整**；取整后 ≤0 则该腿拒挂。
- 现货：交易所没有原生条件单，直接跳过（原因“现货无原生保护单”）；只有 U 本位永续合约真正挂得上。
- `protect_after_entry=False` 时不挂。

### 4.2 OKX（`POST /api/v5/trade/order-algo`，`ordType=conditional`）

| 参数 | 止损腿 | TP1 / TP2 | 说明 |
|---|---|---|---|
| `instId` | 合约 instId（如 `ETH-USDT-SWAP`） | 同 | 按 `market_type` 走 `to_okx_swap_inst_id()` |
| `tdMode` | 跟**持仓真实 mgnMode** | 同 | 与持仓不一致会被 `51023`/`51169` 拒 → 翻转一次重试 |
| `side` | 多头持仓 `sell` / 空头 `buy` | 同 | 平仓方向 |
| `ordType` | `conditional` | `conditional` | 条件单 |
| `reduceOnly` | `true` | `true` | 只减仓（必须） |
| `closeFraction` | `"1"`（全平） | — | 只接受 1；`sz` 与它互斥（50024） |
| `sz` | —（不传） | 张数（`lotSz` 向下取整） | 双向持仓模式下止损退化为固定 `sz` |
| `posSide` | 仅双向持仓模式（long/short）传 | 同 | 净持仓模式传了会 `51010` → 去掉重试一次 |
| `slTriggerPx` / `slOrdPx` | 触发价 / `"-1"` | — | `-1` = 触发后按市价成交 |
| `tpTriggerPx` / `tpOrdPx` | — | 触发价 / `"-1"` | 同上 |

`closeFraction="1"` 的四条硬约束：`sz` 与它互斥（`50024`）、只接受 `1`（`0.5` 报 `51000`）、必须配 `reduceOnly=True`（`51328`）、**双向持仓模式不可用（`51329`）→ 自动退回固定 `sz`**。

### 4.3 Binance（条件单）

| 腿 | 类型 | 关键参数 |
|---|---|---|
| 止损 | `STOP_MARKET` | `stopPrice`、`closePosition="true"`（全平，不受数量精度影响）、`workingType="MARK_PRICE"` |
| TP1 / TP2 | `TAKE_PROFIT_MARKET` | `stopPrice`、`quantity`（分批量）、`reduceOnly="true"`、`workingType="MARK_PRICE"` |

- 双向持仓（hedge）模式：必须给 `positionSide`，且**不能**给 `reduceOnly`（否则 `-1106`），平仓靠 `positionSide` 语义。
- 触发价同样按 tick 取整；`stopPrice` 是字符串，比较时用相对容差。

### 4.4 幂等（重复补挂不叠单、也不留空窗）

挂单前先 `GET /api/v5/trade/orders-algo-pending` 查在挂条件单（OKX）/ 查普通挂单（Binance）：

- **止损**：同方向、价位一致（tick/2 容差）的在挂止损视为已覆盖，跳过；价位不一致则撤旧重挂（`replace_on_mismatch=True`）。
- **止盈**：必须**价位一致且张数覆盖本仓所需**（`_tp_covers(row, price, contracts)`）才算在场；只比价位会让加仓后止盈总量停在第一次开仓的量。
- 补偿链路（`resume_pending_trigger()`）传 `replace_on_mismatch=False`：那时不该撤别人的单；价位不一致的旧止损交给 OKX 回 `51088`（同方向已有止损）后**先撤旧、再按本仓重建**。
- 查询失败按“没有在挂单”处理（宁可重复挂，也不能因一次网络抖动让保护单挂不上）。

## 5. 成交判定与补挂（下单 ≠ 成交）

| 场景 | 判定 | 后续动作 |
|---|---|---|
| 市价单 | 立即成交（`filled=True`） | 直接挂保护单 |
| 限价单挂上 | `state=live` / 无 `avgPx` → `filled=False` | 记 `pending_fill`（含完整 `protection_plan`），**绝不立刻挂保护单** |
| 计划委托（突破单） | `order_id` 是 **algoId**，不能用普通查单接口 | 记 `pending_trigger`，靠 `_trigger_position_evidence()` 证明成交 |
| 查不到成交状态 | `_pending_order_fill()` 返回 `known=False` | 前 2 轮只告警等待，第 3 轮（`_RESUME_UNKNOWN_LIMIT=3`）才按当前持仓兜底，且 `fill_confirmed=False`，钉钉推“未确认成交”核对提示，**不发成交回报** |
| 触发单是否成交 | `opened_at` 与流水时间差 ≤1s，或入场价与触发价差 ≤2%（`_TRIGGER_PRICE_TOLERANCE_PCT=2.0`） | 证明不了就不宣称成交、不拿旧仓当新仓挂保护单 |

- 轮询节奏：守护进程 `PA_DAEMON_POLL_INTERVAL=20s`，每次 tick 调 `resume_pending_trigger()`；两次分析最小间隔 `PA_DAEMON_ANALYSIS_COOLDOWN=120s`。
- `_last_pending_trigger()` 扫描窗口 `_PENDING_SCAN_LIMIT=20000` 行（末尾 80 行会让 `partial`/`gave-up` 记录滑出窗口后永久静默）。
- 缺腿按 `3` 次重试上限；连续失败落 `gave-up` 并告警。
- `resume_pending_trigger()` 开头必须清 `last_resume_failure` 与两个失败计数，否则仓位已平还会每 120 秒推一次裸奔告警。

## 6. 滑点与成交价偏差

- `max_slippage_bps`（默认 `30.0`，即 0.30%）：`|成交均价 − 决策价| / 决策价 × 10000` 超过阈值**只告警**，写入记录 `slippage_bps`，不撤单不拒单（单已成交，拒单只会让仓位裸奔）。
- 限价单成交价通常就是挂单价；市价单/计划委托的实际成交均价才是偏差来源。

## 7. 交易所报错与自愈（保护单三条自愈分支，各只重试一次）

| 代码 | 含义 | 处理 |
|---|---|---|
| `51023` / `51169` | 保证金模式与持仓不符 | 翻转 `tdMode`（cross ↔ isolated）重试一次，只改当前腿 |
| `51010` | posSide 不被接受（净持仓模式） | 去掉 `posSide`，`_pos_mode` 记为 net，重试一次 |
| `51088` | 同方向已有止损 | 撤掉旧止损，按本仓重建 |
| `51329` | 双向持仓不支持 closeFraction | 止损腿退回固定 `sz` |
| `50024` | `sz` 与 `closeFraction` 同时给 | 二选一（止损只给 closeFraction） |
| `51000` | closeFraction 取值非法 | 只接受 `"1"` |
| `51327` | 非合约不支持 closeFraction | 现货本来就不挂 |
| `51328` | closeFraction 缺 reduceOnly | 补 `reduceOnly=True` |
| `51603` | 查单 Order does not exist | 现货 id 查合约单 → `_symbol_for_venue()` 必须按 market_type 产出 instId |
| `-1106`（Binance） | 参数不合法 | hedge 模式不要传 `reduceOnly` |

`payload is None`（网络/HTTP 层失败）**绝不重试**，直接记为失败并把原因写进流水。

| `PA_DAEMON_WAIT_BAR_CLOSE` | 只在K线收盘后分析 | 默认 true |
| `PA_DAEMON_SKIP_DUPLICATE` / `ANALYZE_ON_START` / `INCREMENTAL` / `INCREMENTAL_THRESHOLD` / `LOG_LEVEL` | 其余守护参数 | — |

注意：`min_confidence`、`max_daily_orders`、`allowed_symbols`、`require_stop_loss`、`max_price_deviation_pct` **没有** env 覆盖，只能改 `settings.json`。
